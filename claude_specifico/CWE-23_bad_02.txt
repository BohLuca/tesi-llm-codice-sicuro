REASON: The filename is read directly from `System.in` (untrusted input) and concatenated onto the `root` prefix with no canonicalization or validation, so a value like `../../etc/passwd` escapes the intended `uploads` directory. The `file.exists() && file.isFile()` check only confirms the resolved target exists — it does not verify the path stays within `root`. A correct fix is to resolve the path (e.g. `file.getCanonicalPath()`) and confirm it starts with the canonical form of `root`, or to reject any input containing separators or `..` segments.
